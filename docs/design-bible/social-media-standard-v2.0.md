# Lakive Social Media Internal Standard — v2.0

**Effective:** August 2026  
**Supersedes:** docs/social-media-standard-v1.1.md  
**Applies to:** Instagram · Threads · X · LinkedIn · Facebook · TikTok  
**Status:** Canonical — all posts must clear this standard before publication

---

## 核心原则（Core Principle）

**Every post must be worth saving. Long-term decision value over short-term news.**

Lakive is not a news outlet. Lakive is not an environmental monitor. Lakive is not a generic city guide. Lakive is a research platform that helps people make better long-term settlement decisions using occupation-specific data. Every post must advance this identity — directly or indirectly.

## 一、每日内容日历（Weekly Content Calendar）

每周七天，固定主题。主题名称和徽章文字统一使用下表，不得混用旧版名称。

| 星期 | 英文主题名 | 徽章显示文字 | 核心任务 |
|------|-----------|-------------|---------|
| Monday | Data Pulse | MONDAY · DATA PULSE | 用一组数据揭示城市之间的结构性差异 |
| Tuesday | Lakive Insight | TUESDAY INSIGHT | 一个反直觉结论，配数据支撑 |
| Wednesday | Career Insight | WEDNESDAY · CAREER INSIGHT | 一个职业，跨城市/跨国收入或机会对比 |
| Thursday | City Spotlight | THURSDAY · CITY SPOTLIGHT | 深度解析一座城市，必须含 HEY / LAS / EOI |
| Friday | Weekly Comparison | FRIDAY · WEEKLY COMPARISON | 两到三座城市直接对比，主题明确 |
| Saturday | Framework Education | SATURDAY · LAKIVE EXPLAINED | 解释 Lakive 框架中的一个概念或指数 |
| Sunday | 休息日 / 备用 | — | 不发或发报告推广 |

**Saturday 专项说明：**  
Saturday 从"Discovery"改为"Framework Education"。每周教用户一个 Lakive 概念：什么是 HEY、什么是 LAS 的四个维度、什么是 EOI、四个象限分别代表什么、如何读 Lakive City Matrix™。把 Lakive Dictionary™ 视觉化，每周一个词条。用户记住的不是某一张图，而是理解问题的方式。

## 二、Lakive 框架整合规则（Framework Integration Rules）

### 2.1 HEY / LAS / EOI 必须统一出现

任何涉及城市数据的图（City Spotlight、Data Pulse、Weekly Comparison 等），必须在图中的某处显示该城市的三项指数。最小呈现方式为小字底部栏：

```
Vancouver, BC  ·  HEY 13.0 yrs  ·  LAS 84  ·  EOI 80
```

不允许用替代称呼替换正式名称。对照表如下：

| 错误写法 | 正确写法 |
|---------|---------|
| HPI Years | HEY (Housing Entry Barrier) |
| Years to own | HEY |
| Affordability Index | HEY |
| Livability Score | LAS (Lifestyle Appeal Score) |
| Job Demand | EOI (Employment Opportunity Index) |
| Entry Barrier（求职门槛） | **不是 HEY** — 如果指求职难度，用"Job Entry Difficulty"，不要用 HEY 的同名词 |

### 2.2 HEY 值必须带单位

引用 HEY 值时，永远写"X.X years"或"X.X 年"，不允许单独写"HEY = 13.0"。正确：HEY = 13.0 years。

### 2.3 The Lakive City Matrix™ 作为定期锚点

每月至少出现一次完整的 Lakive City Matrix™ 气泡图（静态版本）。可配合报告发布、月度数据更新或 Saturday Framework Education 发布。图中™符号必须出现。

### 2.4 四象限名称不可修改

- Global Gems
- Aspirational Cities  
- Settlement Sweet Spot
- High-Cost Trade-off

社媒文案中引用时首字母大写，不缩写，不意译。

## 三、数据规则（Data Rules）

### 3.1 数据年份一致性（新增，强制）

**同一张图内，加拿大数据和美国数据必须来自同一数据年度，或差距不超过12个月。**

如确实存在数据年份差异（例如加拿大职业数据更新周期更长），必须在图中明确注明每项数据的来源年份。不允许在同一张对比图中，一方使用2021年数据、另一方使用2025年数据而不加说明。

违规示例（已发布，不再修改，但以后不重复）：
> 牙医收入对比：加拿大数据来自2021人口普查，美国数据来自2025年BLS — 两者差4年，图中未注明。

### 3.2 批准数据源（Approved Data Sources）

**加拿大：**
- Statistics Canada — Labour Force Survey, Census, SLID
- Canada's Job Bank — 职位空缺与需求信号
- CMHC — 住房数据、租金数据
- Rentals.ca — 月度全国租金报告
- CREA — 房价数据（每月15–18日更新）
- CRA / 各省税表 — 税后收入估算
- Lakive city-occupation index — 内部指数（需注明版本月份）

**美国：**
- Bureau of Labor Statistics (BLS) — OEWS职业收入、就业数据
- U.S. Census Bureau / ACS — 收入与住房数据
- HUD — 公平市场租金
- IRS / 州税表 — 税后收入估算

**第三方排名引用：**
- 引用时必须注明原始排名名称和发布机构
- 禁止将第三方排名数字作为 Lakive 自身指数展示
- 对第三方排名进行批评性分析时（如 Workcation Mirage 报告风格），必须明确区分"他们的数字"和"Lakive 的数字"

### 3.3 数据时效要求

- 就业/失业率数据：不超过3个月前的发布数据
- 租金数据：不超过2个月前
- 房价数据：不超过2个月前（CREA月报）
- 收入/职业数据：不超过18个月前（可接受年度数据）
- 如超过上述时限，必须在图中注明"数据日期"并说明为何使用旧数据

## 四、内容边界规则（Content Scope Rules）

### 4.1 Lakive 发布的内容类型

✅ 允许发布：
- 城市与城市之间的定居数据对比（住房、收入、就业、生活成本）
- 职业维度的城市分析（特定职业在不同城市的收入、HEY、EOI）
- Lakive 指数解读（HEY / LAS / EOI 框架教育）
- Lakive 报告推广（研究发现摘要、数据图表、引导阅读完整报告）
- 宏观经济数据解读（BoC 利率、CPI、失业率）— 必须折射回城市定居影响
- 城市政策新闻评论 — 必须有 Lakive 角度（"这对 HEY 意味着什么"）

### 4.2 禁止发布

❌ 禁止发布（无论热度多高）：
- 实时灾害、天气、空气质量预警（山火、洪水、地震等）
- 政治选举表态或候选人评论
- 非城市定居相关的人文/历史内容（"城市有趣冷知识"等）
- 通用生活技巧、心灵鸡汤
- 没有折射回 Lakive 框架的通用统计数字（"加拿大人每年通勤250小时"单独发布）

### 4.3 "折射回框架"规则

如果一条新闻或数据本身不直接属于 Lakive 领域，必须通过 Lakive 框架折射后才能发布。

示例：
> ❌ 错误："加拿大山火导致西部空气质量下降" → 直接发布 AQHI 数据  
> ✅ 正确："持续的山火风险是 Lakive LAS 评分中环境维度的组成部分——这就是为什么卡尔加里的 LAS 气候分项低于温哥华"

> ❌ 错误："加拿大人每年通勤250小时" → 单独发布  
> ✅ 正确："在温哥华，平均通勤时间是卡尔加里的1.6倍。HEY 13.0年买不到家，每天的通勤成本也在消耗你的时间资产。"

## 五、内容公式库（Content Formula Library）

以下是经过验证的有效内容公式，新内容优先套用。

### 公式一：≠ 公式（Contrast Formula）
```
[直觉认知] ≠ [Lakive 揭示的真相]
```
示例：Higher Salary ≠ Better Affordability / High Demand ≠ Easy Entry  
规则：左边是大众假设，右边是数据驱动的修正。必须用数据支撑，不能只是口号。

### 公式二：城市裁决（City Verdict）
```
[城市名] verdict: [一句话总结定居价值判断]
```
示例：Calgary verdict: Underrated by lifestyle indices, overperforming on the variables that determine long-term financial wellbeing.  
规则：语气客观，不用"最好"或"最差"，用"对谁而言"框架。

### 公式三：职业×城市（Occupation × City）
```
[职业]，在[城市A]：[数字]。在[城市B]：[数字]。
同一份职业，不同的人生轨迹。
```
示例：牙医收入对比、软件工程师 HEY 对比  
规则：职业必须是真实的、有代表性的（护士、电工、教师、工程师等），不限于知识工作者。

### 公式四：象限揭示（Quadrant Reveal）
```
[城市] 在 Lakive City Matrix™ 中属于 [象限名称]。
这意味着：[一句话解释]。
```
示例：Vancouver 属于 Aspirational Cities —— 高度宜居，但大多数职业在入住阶段面临巨大财务压力。

### 公式五：框架教育（Saturday Formula）
```
什么是 [HEY / LAS / EOI / 象限名]？
[定义] · [计算方式简述] · [在图中的作用] · [实际案例]
```

## 六、每日内容具体要求（Daily Content Requirements）

### Monday — Data Pulse
**目的：** 用数据开启工作周，建立 Lakive 作为"数据来源"的权威感  
**内容结构：** 一个核心数据 → 城市间对比 → Lakive 结论  
**必须包含：** 数据来源（机构+月份）、至少2座城市的对比  
**禁止：** 单城市数据（无对比没有意义）  
**推荐题材：** 失业率、租金数据、房价数据、就业数据（每月更新后第一个Monday优先发布）  
**HEY/LAS/EOI：** 如提及城市，底部显示三项指数

### Tuesday — Lakive Insight
**目的：** 建立 Lakive 的观点权威，让用户保存分享  
**内容结构：** 反直觉结论（headline）→ 数据支撑 → "这对你意味着什么"  
**必须包含：** ≠ 公式或城市裁决公式  
**禁止：** 没有 Lakive 独特角度的通用数据  
**推荐题材：** 薪资与可负担性的背离、全球排名与定居现实的落差、税后收入的城市差异  
**HEY/LAS/EOI：** 必须至少出现一项指数数值

### Wednesday — Career Insight
**目的：** 服务正在做职业+城市决策的用户，建立职业维度的搜索入口  
**内容结构：** 职业名 → 跨城市/跨国收入或HEY对比 → 方法论注释  
**必须包含：** 职业名（NOC/SOC代码建议附注）、数据年份、数据来源  
**数据年份规则：** 加拿大与美国数据年份差不超过12个月，否则必须分别注明  
**禁止：** 使用超过2年的收入数据而不注明  
**职业选题优先级：** 护士、电工、教师、工程师、软件工程师、会计、厨师、司机、建筑工人、药剂师  
（偏向蓝领和中等收入职业，这是 Lakive 差异化定位的核心用户）

### Thursday — City Spotlight
**目的：** 深度解析一座城市，成为该城市相关搜索的权威参考  
**内容结构：** 城市名 + 标签 → 5项指标（Housing/Jobs/Cost of Living/Environment/Lifestyle）→ Lakive Insight 结语  
**必须包含：** HEY（使用"Housing Entry Barrier (HEY)"，单位 years）、LAS 评分、EOI 评分  
**禁止：** 使用"HPI Years"或其他替代称呼替代 HEY  
**数据规则：** 所有指标注明来源和数据年份  
**Lakive Insight 结语格式：** "这座城市的优势不是X，而是Y与Z的组合。"（参考 Boston 那张的格式，是正确的）

### Friday — Weekly Comparison
**目的：** 给用户一个每周固定的"城市对比"节目，建立习惯  
**内容结构：** 明确对比主题 → 2–3座城市并排数据 → 一句结论  
**必须包含：** 数据来源（机构+月份）、对比维度清晰（不要把职业、住房、就业混在一张图里）  
**禁止：** 超过3座城市的对比（视觉太挤，信息稀释）  
**推荐题材：** 失业率对比、租金对比、HEY对比、LAS/EOI对比  
**Insight 结语：** 必须有一句 Lakive 结论，不能只陈列数据

### Saturday — Framework Education（Lakive Explained）
**目的：** 每周用一张图让用户更深理解 Lakive 的分析框架  
**内容结构：** 概念名称 → 定义 → 计算逻辑简述 → 实际数据案例 → 引导去 lakive.com  
**选题轮换（建议每8周一个周期）：**
1. 什么是 HEY — Housing Entry Barrier
2. 什么是 LAS — Lifestyle Appeal Score 及四个维度
3. 什么是 EOI — Employment Opportunity Index
4. Global Gems — 这个象限意味着什么
5. Aspirational Cities — 数字背后的代价
6. Settlement Sweet Spot — 被低估的城市在哪里
7. High-Cost Trade-off — 什么时候高成本没有匹配回报
8. 如何读 Lakive City Matrix™ 完整图

## 七、报告推广规范（Report Promotion）

### 7.1 发布时机
- 报告上线当天：发布3张卡片的推广轮播（格式参考"Canada's Cities on the Rise 2026"三联卡）
- 上线后第3天：发布核心数据图（单张，最有争议或最反直觉的一个发现）
- 上线后第7天：发布用户引导图（"你在哪个象限？"或"你的职业在哪座城市最划算？"）

### 7.2 三联卡格式
- 第1张：报告标题 + 副标题 + 研究范围（城市数、职业数、数据期）
- 第2张：Key Findings（3–4条，每条一个城市，一句话结论）
- 第3张：阅读引导 + 报告封面视觉 + lakive.com/reports

### 7.3 报告引用规则
- 社媒图中引用报告数据时，注明"Lakive Research, [月份年份]"
- 不要引用"待发布"报告的数据 — 数据发布与报告发布同步

沿用 v1.1 §1 全部规定，补充以下：

## 十五、发布前 QA 检查清单（Pre-Publish QA Checklist）

发布前逐项确认：

**品牌**
- [ ] Logo 使用官方版本，tagline 无句号
- [ ] 字体 Inter Bold / Inter Regular / IBM Plex Mono
- [ ] 配色符合 v1.1 §1 调色板

- [ ] 内容属于"允许发布"类别（见第四节）

- [ ] 内容主题与当天固定系列匹配
- [ ] 徽章文字使用当前版本名称（见第一节表格）

**可读性**
- [ ] 对比度 ≥ 4.5:1（正文），≥ 3:1（大数字展示）
- [ ] 最小渲染字号 ≥ 20px（1080px画布）
- [ ] QR码已扫描测试（如有）
